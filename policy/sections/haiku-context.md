## Haiku context discipline
- Haiku bills about five times its base rate for any request whose prompt exceeds 100K tokens; that is still about a quarter of Sonnet's price, so a finished Haiku task is worth more than a small context.
- Keep Haiku tasks narrow: exact paths and line ranges, at most {{skill_cap_haiku}} skills, and an instruction not to read beyond them.
- Executors start on Haiku, Sonnet-planned tasks included (on `exec-haiku-high`), so planners split work until each task needs at most {{skill_cap_haiku}} skills.
- Tier agents start without the user's and the project's CLAUDE.md files (`omitClaudeMd`), so their fixed context is the agent body, the tool definitions, the environment and the skill listing that comes with the Skill tool (roughly 15K tokens with several hundred skills installed); the project rules files and SKILL.md files they load come on top. Haiku tier agents run on Haiku's full context window (1M tokens in Claude Code) and do not compact early: early compaction restarted them at 33-62K tokens, made them re-read the same files and killed some by thrashing. The audit flags a Haiku agent whose prompt passes {{haiku_prompt_flag_tokens}} tokens; that task should have been split. Where the project rules files are large, name only the rules a task needs on its Project rules line.
