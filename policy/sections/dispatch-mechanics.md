## Dispatch mechanics (verified on Claude Code 2.1.306, 2026-10-24)
- Never pass `model` or `effort` on any Agent call; either one overrides the frontmatter.
- Never set `CLAUDE_CODE_EFFORT_LEVEL` (it overrides every agent's frontmatter effort, so a shell profile or tool that exports it breaks routing) or `CLAUDE_CODE_SUBAGENT_MODEL` (and never `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`). The session-start context warns when it sees any of them.
- Nesting is blocked in four layers: each agent's `disallowedTools` (`Agent, TeamCreate, TeamDelete, SendMessage`), its `tools` allowlist, its body, and `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` in the settings env. On Claude Code 2.1.318, a skill with `context: fork` that a subagent invokes through the Skill tool runs as a separate `general-purpose` subagent that none of these layers stops, so the dispatch guard checks Skill calls too (next bullets).
- The advisor cannot be removed per agent on this version (no frontmatter field; `disallowedTools: advisor` does not detach it, because it is a server tool). The restriction for non-planners is the body line "Never consult the advisor." plus the same line in every non-planner delegation message.
- Agent definitions reach a running session late. After the plugin is installed, enabled or updated, run `/reload-plugins` or start a fresh session before dispatching; if a tier type is reported missing, retry shortly or run the delegation in a fresh `claude -p` session. On 2026-10-24, one of three parallel `exec-haiku-low` launches right after a body change still got the old body, so after changing agent definitions, check the first reports for the new behavior.
- Resume an agent instance (FIX, REPLAN, NEED_EVIDENCE answers, gate failures) with SendMessage to its name or agentId, naming the input file paths and a new Output file. A planner instance is resumed only for its own plan (Full lane workflow, step 2).
- The plugin's PreToolUse hook (`scripts/dispatch_guard.py`, matcher `Agent|Task|Skill`) denies any Agent or Task call whose subagent type is neither a tier nor listed in `dispatch.allow_agents` of the routing config (an empty type counts as `general-purpose`; `fork` and `general-purpose` are denied), any `model` or `effort` parameter on any agent, and a tier delegation without a Skills line (`none` or existing absolute SKILL.md paths), without an `Output:` line with an absolute path, or, for non-planners, without "Never consult the advisor." It recognizes both `{{plugin_name}}:<name>` and bare tier names. A blocked call returns the reason; fix the message and resend. For a call that comes from a subagent (the hook event carries `agent_id`), it also denies any Agent or Task call, and a Skill call whose SKILL.md sets `context: fork` or that it cannot find among the user, project and plugin skills; if that check fails internally, it denies. A denied agent can still Read the SKILL.md path on its Skills line and follow it inline.
- Tier agents run with `omitClaudeMd: true`: they start without user or project CLAUDE.md files and read the project rules files their delegation names. Every role has Read, Write and the Skill tool; with the Skill tool, Claude Code (2.1.318) attaches the session's skill listing to an agent's first prompt, roughly 15K tokens with several hundred skills installed. Agents load the skills their Skills line names, by Read of the SKILL.md path or with the Skill tool. Roles with Bash also have Monitor and TaskStop, because Bash refuses `sleep N` followed by other commands and points to Monitor. On Claude Code 2.1.312, `omitClaudeMd` does not cover nested memory: when an agent touches a file, Claude Code still attaches the CLAUDE.md files (with their imports) of the directories between the session's launch folder and that file, and user rules whose `paths:` match it. No plugin setting stops this. Launch Claude Code in the project root to keep the project's and the workspace's CLAUDE.md files out of tier agents; the session audit flags every tier agent that still received one. Built-in commands that spawn other agent types (`/code-review`, `/simplify`, `/security-review`) are denied unless their type is allowlisted.
