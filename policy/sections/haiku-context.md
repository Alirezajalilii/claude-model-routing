## Haiku context discipline
- Haiku bills about five times more for any request whose prompt exceeds 100K tokens.
- Keep Haiku tasks narrow: exact paths and line ranges, at most {{skill_cap_haiku}} skills, and an instruction not to read beyond them.
- Executors start on Haiku, Sonnet-planned tasks included (on `exec-haiku-high`), so planners split work until each task needs at most {{skill_cap_haiku}} skills.
- Tier agents start without the user's and the project's CLAUDE.md files (`omitClaudeMd`), so their fixed context is the agent body, the tool definitions, the environment and the skill listing that comes with the Skill tool (roughly 15K tokens with several hundred skills installed); the project rules files and SKILL.md files they load come on top. Haiku tier agents compact once their context passes about 90K tokens (`autoCompactWindow` 123000: Claude Code compacts 33K below that window, its 20K output reserve plus a 13K buffer), and the audit flags every Haiku request over {{haiku_prompt_flag_tokens}} prompt tokens. Where the project rules files are large, name only the rules a task needs on its Project rules line.
